## RECOMMENDATIONS

- **Required-field validation**  
  - Implement and surface inline error messages for required fields (First Name, Email ID, Mobile Number, Last Name) on blur and/or on attempted submission.  
  - Ensure errors are tied to the fields with `aria-describedby` for accessibility.

- **Last Name persistence bug**  
  - Investigate why `lastName` reverts to a previous valid value when a new (potentially invalid) value is entered.  
  - If special characters are disallowed, show a clear validation error and keep the user’s raw input so they can correct it, rather than reverting silently.

- **Consistency of special-character handling**  
  - Current behavior strips special characters in First/Middle Name silently. Consider either:  
    - Allowing a wider set of characters (apostrophes, hyphens, etc.), or  
    - Explicitly validating and messaging when characters are removed/invalid, so users understand what happened.

- **Profile picture upload**  
  - Expose a standard (even if hidden) `<input type="file">` associated with “Add profile picture” to support automation and accessibility tools.  
  - Ensure there is a visible confirmation (filename or thumbnail) after upload.

- **Accessibility considerations**  
  - Verify that all error messages (once implemented) are announced via `role="alert"` or similar with appropriate `aria-live` regions.  
  - Confirm all buttons and fields have descriptive labels (already good for main fields) and logical tab order.  

- **Further testing**  
  - Perform form-level submission tests to confirm that, even if inline errors are missing now, the backend or client-side logic actually blocks submission when required fields are empty.  
  - Add tests for invalid formats (e.g., malformed email, non-numeric mobile) and max-length constraints across all name fields.
