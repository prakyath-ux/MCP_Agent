## RECOMMENDATIONS

- **Implement consistent required-field validation**  
  - Add client-side and/or server-side validation (with inline messaging) for First Name, Email ID, Mobile Number, and Last Name when left empty.  
  - Ensure error messages are clearly associated with fields (e.g., aria-describedby) and appear on blur and/or on attempt to continue.

- **Improve format validation**
  - **Email ID**: Enforce a stricter email pattern (must contain `@` and domain, disallow plain text like `MARISA.EXAMPLE.COM`). Keep plus-addressing compatible.
  - **Mobile Number**: For inputs longer than 7 digits, apply truncation/masking instead of clearing the field. Optionally provide an error if the format is invalid.

- **Handle disallowed characters explicitly**
  - If certain characters are not allowed in First Name (like `!`), show a clear validation message instead of silently clearing the value.
  - Current behavior for Last Name and Middle Name allows apostrophes, hyphens, and periods and seems acceptable; if there are business rules, make them consistent across name fields.

- **Dropdown automation & robustness**
  - For the Branch field, the current automated selector (`button:has(span:contains("Select Branch"))`) is not valid CSS. Update automation locators (e.g., use `button` text or data attributes) so that tests can reliably open and select options.
  - From an implementation perspective, ensure the dropdown is keyboard-accessible and exposes role/listbox/option semantics for accessibility.

- **Accessibility considerations**
  - Add ARIA attributes or proper `<label for>` wiring so errors are announced by screen readers.
  - Ensure required fields include `aria-required="true"` and that error text uses `[role="alert"]` or equivalent.
  - Confirm that masked mobile input communicates its required format (e.g., helper text: “Enter 7‑digit local number”).

- **Further testing**
  - Re-test required-field behaviors when attempting to **Save & Continue** to verify whether validation is enforced server-side even though no inline error appears.
  - Expand tests for extreme inputs (very long names/emails, non-numeric mobile input, copy-paste behaviors) once these primary validation issues are addressed.
