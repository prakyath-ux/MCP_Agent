## RECOMMENDATIONS

1. **Validation behavior**
   - Implement and/or expose **required-field validation** for:
     - First Name
     - Email ID
     - Mobile Number
     - Last Name  
     Errors should surface on blur or on form-level validation, with clear messages like “First Name is required.”
   - Add **email format validation** (HTML5 or custom) to `Email ID`. Reject values without `@` and a valid domain; show message such as “Enter a valid email address.”

2. **Input sanitization vs. user feedback**
   - Current behavior silently strips numerics from First/Last Name and clears invalid mobile inputs. Prefer:
     - Either blocking forbidden characters as the user types with subtle cues, or
     - Allowing typing but showing explicit inline error messages when invalid.
   - For Mobile Number, do not clear valid numeric values without explanation. If a specific pattern is required, show a message (e.g., “Enter a 7-digit number; country code +1868 is prefilled.”).

3. **Mobile number control**
   - Ensure that:
     - The internal value is preserved after input, and
     - Any masking logic still leaves a stable, readable value in the textbox.
   - Add explicit messaging for length/format requirements and for non-numeric characters.

4. **Branch dropdown accessibility**
   - Use standard ARIA roles (`role="combobox"`, `role="listbox"`, `role="option"`) and explicit attributes for the options list and search field.
   - Ensure the internal “Search...” input is detectable via standard selectors (`input[placeholder="Search..."]` or `role="searchbox"`). This will improve both assistive tech compatibility and automated testability.

5. **General UX and accessibility**
   - Provide consistent helper text or error text regions with `role="alert"` and/or `aria-live="polite"` for all validated fields.
   - Verify keyboard navigation:
     - Tab order follows the visible sequence (First Name → Email → Middle Name → Mobile → Last Name → Branch → Save buttons).
     - Dropdown can be opened and navigated via keyboard.
   - Consider adding inline hints for auto-uppercase behavior so users understand why their input changes.

These changes will make validation more transparent to users, reduce confusion when characters or entire values disappear, and improve both accessibility and automated test coverage.
