## RECOMMENDATIONS

1. **Implement and/or surface required-field validation**  
   - First Name, Email ID, Mobile Number, and Last Name all appear marked required but allow empty submission with no inline error signal.  
   - Add client-side checks that show clear messages (e.g., “First Name is required”) on blur or on attempted submission, and ensure assistive technologies can read them (ARIA `role="alert"` or `aria-describedby`).

2. **Fix special-character handling in name fields and mobile number**
   - Current behavior clears the entire field when encountering disallowed characters, without feedback.  
   - Prefer either:
     - Allowing common characters (apostrophes, hyphens) in names, or  
     - Showing an explicit validation message if characters are disallowed.  
   - For mobile, entering more digits than the mask supports should either:
     - Truncate gracefully to the maximum, or  
     - Show a clear error if the number is invalid—not clear the field.

3. **Add proper email format validation**
   - Reject values without `@` and domain (e.g., `INVALID.EMAIL`) with an inline error and appropriate ARIA markup.
   - Consider normalizing case but not relying solely on that as validation.

4. **Review Branch dropdown implementation and selectors**
   - Ensure the Branch selection control is discoverable via stable attributes (e.g., `data-testid`, `name`, or `aria-label`).  
   - This will help both automation and accessibility (screen readers need clear labels on that trigger).

5. **Verify and harden profile picture upload UX**
   - Confirm that users see a clear state change (thumbnail, filename, or “Re-upload” text) after a successful upload.  
   - Ensure the `<input type="file">` or trigger is properly labeled (`aria-label` or visible text) and keyboard accessible.

6. **Accessibility considerations**
   - Ensure all validation errors are:
     - Programmatically associated with their inputs (`aria-describedby`), and  
     - Announced to screen readers (e.g., using `role="alert"` or `aria-live`).  
   - Verify all buttons (Save & Exit, Save & Continue, Select Branch, Add profile picture) have accessible names matching visible labels and are reachable via keyboard.

7. **Areas for deeper testing**
   - Cross-field behaviors (e.g., what happens when user tries to Save & Continue with all required fields empty—currently required validations seem absent).  
   - Edge cases for maximum lengths in name and email fields, and alternate valid email formats (subdomains, long TLDs).  
   - Mobile number behavior with non-numeric characters and copy/paste scenarios.
