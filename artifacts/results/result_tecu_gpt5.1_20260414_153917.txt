## RECOMMENDATIONS

1. **Inline required-field validation**
   - Implement or surface inline error states (with `.MuiFormHelperText-root.Mui-error` or similar) for:
     - First Name (empty)
     - Email ID (empty)
     - Mobile Number (empty)
     - Last Name (empty)
   - Ensure errors appear on blur or on form submit, but remain visible for accessibility (ideally `role="alert"` or `aria-live` region).

2. **Mobile number validation**
   - Enforce minimum/maximum length and valid pattern for `primaryMobileNo`.
   - On invalid formats (e.g., too short like `"12345"`), show a clear message such as “Enter a valid 7‑digit mobile number” (or whatever the expected rule is).
   - Confirm masking/formatting does not suppress validation events.

3. **Branch dropdown behavior**
   - Investigate why selecting `"100 - TECU - MARABELLA BRANCH"` does not update the trigger label (stays “Select Branch”).
   - Common causes:
     - Click handler attached only to certain option container; the text node click might not trigger selection.
     - State not bound correctly to the trigger button label.
   - Fix so that after selection the button text reliably reflects the chosen branch and remains so on blur.

4. **Email validation robustness**
   - Currently, even addresses with `+` and `!` in the local part are accepted without error.
   - If business rules require stricter validation, refine the pattern and ensure appropriate error messages. If such addresses are valid per requirements, document this explicitly.

5. **Profile picture upload (future testing)**
   - For TC17, once file upload via automation is allowed:
     - Expose the underlying `<input type="file">` for easier automated access.
     - Provide clear UI feedback after a file is chosen (thumbnail or filename + accessible status text).

6. **Accessibility considerations**
   - Ensure all error messages for the above fields are:
     - Programmatically associated with inputs via `aria-describedby`.
     - Announced via `role="alert"` or `aria-live="assertive"`.
   - Confirm the Branch dropdown uses appropriate ARIA roles (`button`, `listbox`, `option`) and updates `aria-expanded`/`aria-activedescendant` when opened and when an option is selected.

7. **Areas for deeper testing**
   - Cross-field validations (e.g., duplicate mobile/email, format vs. country code).
   - Behavior on actual submission (not covered here per navigation restriction) to confirm server-side validations mirror and reinforce the client-side rules.
   - State persistence when navigating away and back via “Save & Exit” / “Save & Continue” once allowed to be clicked in a broader test cycle.
