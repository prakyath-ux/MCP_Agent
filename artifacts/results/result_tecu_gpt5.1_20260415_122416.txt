## RECOMMENDATIONS

1. **Inline required-field validation**
   - Add or confirm blur-level validation for First Name, Email ID, Mobile Number, and Last Name. Users should see immediate feedback when leaving required fields empty, not only on form submit/continue.
   - Ensure error messages are exposed with appropriate roles/classes (e.g., `role="alert"` or helper text with error classes) so automated checks and assistive tech can detect them.

2. **Validation timing and UX**
   - If validation is deferred to “Save & Continue”, consider at least:
     - Marking invalid fields with a visible error state once the user attempts to continue.
     - Moving focus to the first invalid field with a clear message.
   - Align implemented behavior with the defined test plan expectations (which assume inline required validation).

3. **File upload testability**
   - For automated testing, provide a stable file path or test fixture instead of `AUTO`, or ensure that the test harness resolves `AUTO` to a real path.
   - Confirm that the underlying `<input type="file">` remains discoverable in the DOM after triggering the upload UI, so automated upload flows can work reliably.

4. **Accessibility considerations**
   - Ensure all error messages for the required fields are:
     - Programmatically associated with their inputs (`aria-describedby` or similar).
     - Announced to screen readers via `role="alert"` or `aria-live` regions.
   - Verify that the custom Branch dropdown is keyboard-navigable and that the current selection is announced correctly.

5. **Areas for deeper testing**
   - **Email ID**: Negative test cases (clearly invalid formats) on “Save & Continue” to verify robust email validation beyond simple presence.
   - **Name fields**: Boundary testing on max length and character sets, especially for international names.
   - **Mobile Number**: Non-numeric input handling, paste behavior, and error handling when entering fewer than 7 digits.
   - **Profile picture upload**: File type and size restrictions, error handling for invalid files, and behavior on re-upload.
