## RECOMMENDATIONS

1. **Fix required-field validation for First Name and Email ID**
   - Ensure that:
     - Required attributes / validation rules are enforced on blur and/or when moving focus away.
     - Inline helper/error text is rendered within the `.MuiFormControl-root` (or equivalent wrapper) so it can be discovered in the DOM.
   - Add unit/integration tests for:
     - First Name = `""`
     - Email = `""`
   - Confirm consistent behavior with other required fields (Mobile Number, Last Name, Branch) when those are implemented.

2. **Clarify name-field character rules**
   - Current behavior allows:
     - First Name: `ly-dia_anne` (hyphen + underscore) with no error.
     - Middle Name: `a_n-ne.` (underscore, hyphen, trailing period) with no error.
   - Decide business rules:
     - If only alphabetic and maybe hyphen/apostrophe are allowed, update validation and provide clear helper text or inline error.
     - If broader character sets are acceptable, document this in requirements and consider adding placeholder/helper text to guide users.

3. **Ensure required validation is consistent across all required fields**
   - Once additional tests are run, verify:
     - Mobile Number rejects empty and too-short inputs with clear messages.
     - Last Name and Branch behave similarly to First Name / Email after fixes.
   - All required fields should:
     - Show a consistent error style (color, icon, placement).
     - Use consistent wording (e.g., “This field is required” vs “First Name is required”).

4. **Accessibility and testing improvements**
   - Make sure error messages are:
     - Associated with inputs via `aria-describedby`.
     - Announced by screen readers when they appear.
   - For dropdowns and embedded search:
     - Ensure the Branch selector continues to use accessible roles (button + listbox) and that the search field is discoverable and labeled.
   - For automated QA:
     - Keep error messages within predictable containers (e.g., `.MuiFormHelperText-root`) to allow robust selectors for test automation.
     - Consider adding data-testid attributes to critical fields and buttons (`firstName`, `email`, `saveContinue`, `saveExit`) to stabilize tests.

5. **Future deeper testing**
   - Email format:
     - Add negative test cases (e.g., `user@`, `@domain.com`, `user@domain`, `user@domain..com`) to confirm proper format validation.
   - Mobile number:
     - Validate length, digits-only constraint, and masking behavior across several inputs.
   - Navigation buttons:
     - Once allowed by test protocol, verify that “Save & Continue” and “Save & Exit” correctly perform save operations, handle validation blocking, and maintain data when revisiting the form.
