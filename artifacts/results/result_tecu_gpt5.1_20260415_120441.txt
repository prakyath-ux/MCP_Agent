## RECOMMENDATIONS

1. **Implement consistent required-field validation**
   - First Name, Last Name, Email, and Mobile Number all show `*` but do not display inline errors when emptied.
   - Add on-blur and on-submit checks that surface clear messages (e.g., “First Name is required”) whenever these fields are empty.
   - Ensure the error state is also considered in overall form progression logic (even though Submit/Continue wasn’t tested here).

2. **Avoid silent data transformations/reversions**
   - For First/Middle/Last Name, the system currently strips/rejects special characters or reverts to previous values with no notice.
   - If business rules forbid certain characters, show explicit validation messages rather than silently altering input.
   - Consider allowing common name punctuation (apostrophes, hyphens, spaces) or get product clarification; current behavior blocks realistic names.

3. **Clarify Email validation behavior**
   - Required and format rules should be clearly differentiated:
     - Empty → “Email is required.”
     - Invalid non-empty (e.g., `MARISA!TEST@EXAMPLE.COM`) → “Please enter a valid email address.”
   - Ensure the error is cleared once a valid email is provided.

4. **Profile picture upload**
   - Investigate why a file upload immediately triggers `"Only JPEG, JPG, or PNG files are allowed."`
     - Verify accepted MIME types and file extensions.
     - Confirm that uploads from standard clients (including automated test runners) are treated like normal browser uploads.
   - On success, consider showing a thumbnail or filename for clear confirmation.

5. **Accessibility and UX**
   - Ensure error messages:
     - Are programmatically associated with fields via `aria-describedby` or similar.
     - Announce correctly through the existing `alert` live region when validation fails.
   - For masked fields (Mobile Number), provide formatting hints and ensure the mask does not silently discard user keystrokes without explanation.
   - For required fields, consider adding descriptive helper text (e.g., “Fields marked * are mandatory”) and clear error styling (color, icon, message).

6. **Areas for deeper testing**
   - Form-level submission validation: verify that Save & Continue cannot proceed when required fields are invalid or empty.
   - Cross-field interactions (e.g., Mobile Number + country code, email uniqueness if applicable).
   - Boundary conditions: maximum lengths for names, email, and phone; behavior on copy/paste; non-numeric input in Mobile Number.
   - Full profile photo flow: successful upload, preview display, replacement, and removal if supported.
